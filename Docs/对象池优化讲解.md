# 对象池优化讲解

## 一、为什么需要对象池？

### 原来的问题

每次射箭都走这个流程：

```
PlayerBow.Shoot()
    → Instantiate(arrowPrefab)   ← 创建新 GameObject（分配内存）
    → Arrow.Start()
        → Destroy(gameObject, 1) ← 1秒后销毁（释放内存）
```

**每射一箭 = 一次 Instantiate + 一次 Destroy。**

频繁的 Instantiate/Destroy 会导致：

- **GC（垃圾回收）压力**：每次 Instantiate 分配内存，每次 Destroy 释放内存，GC 间歇性卡顿
- **性能浪费**：箭矢的 Rigidbody2D、SpriteRenderer、Collider2D 等组件每次都要重新创建

### 对象池的思路

> **不销毁，只隐藏。用的时候拿出来，不用了放回去。**

```
首次射箭：Instantiate 创建箭矢 → 使用 → 1秒后隐藏（放回池中）
第二次射箭：从池中取出刚才的箭矢 → 重置状态 → 使用 → 1秒后放回
第三次射箭：同上...
```

**只在池空时才 Instantiate，大部分情况下都是复用。**

## 三、代码逐行讲解

### 3.1 IPoolable 接口

```csharp
public interface IPoolable
{
    void OnGetFromPool();    // 从池中取出时调用
    void OnReturnToPool();   // 归还池中时调用
}
```

**作用**：让 PoolManager 知道"这个对象需要特殊处理"。

- `OnGetFromPool`：每次取出时初始化（设伤害值、启动计时器）
- `OnReturnToPool`：每次归还时重置（清速度、恢复精灵、脱离父级）

> 类比：租自行车。取出时调座椅高度（OnGetFromPool），还车时把车擦干净（OnReturnToPool）。

### 3.2 PoolManager 单例

```csharp
public class PoolManager : YSingleton<PoolManager>
{
    // 每个预制体对应一个队列
    private Dictionary<GameObject, Queue<GameObject>> pools;
    // 实例 → 所属预制体的映射
    private Dictionary<GameObject, GameObject> instanceToPrefab;
}
```

**核心数据结构**：

| 字典                 | 键    | 值           | 作用          |
| ------------------ | ---- | ----------- | ----------- |
| `pools`            | 预制体  | 该预制体的空闲对象队列 | 按预制体分类管理    |
| `instanceToPrefab` | 实例对象 | 创建它用的预制体    | 归还时知道放回哪个队列 |

#### Get 方法（取出）

```csharp
public GameObject Get(GameObject prefab, Vector3 position, Quaternion rotation)
{
    // 1. 确保有对应队列
    // 2. 从队列取一个非空对象
    // 3. 队列空 → Instantiate 新对象，记录映射
    // 4. 设置位置旋转
    // 5. SetActive(true)
    // 6. 调用 OnGetFromPool()
}
```

#### Return 方法（归还）

```csharp
public void Return(GameObject obj)
{
    // 1. 查找该实例属于哪个预制体
    // 2. 调用 OnReturnToPool()（对象仍激活，可停协程）
    // 3. 脱离父级（transform.SetParent(null)）
    // 4. SetActive(false)
    // 5. 放回队列
}
```

#### 额外方法

| 方法                       | 作用         | 何时用            |
| ------------------------ | ---------- | -------------- |
| `Prewarm(prefab, count)` | 提前创建 N 个对象 | 场景初始化时，避免运行时卡顿 |
| `Clear(prefab)`          | 清空指定池      | 场景切换时          |
| `ClearAll()`             | 清空所有池      | 游戏退出时          |

### 3.3 Arrow\.cs 修改了什么

#### 原来

```csharp
private void Start()
{
    Destroy(gameObject, lifeSpan);      // ❌ 1秒后销毁
    damage = StatsManager.Instance.GetDamage();
}
```

#### 现在

```csharp
private void Awake()
{
    originalSprite = spriteRenderer.sprite;  // 只执行一次，记录原始精灵
}

// ──── IPoolable 实现 ────

public void OnGetFromPool()              // 替代原 Start()
{
    damage = StatsManager.Instance.GetDamage();
    returnCoroutine = StartCoroutine(ReturnAfterDelay(lifeSpan));  // 启动归还计时器
}

public void OnReturnToPo
ol()             // 新增：重置状态
{
    StopCoroutine(returnCoroutine);      // 停计时器
    rb.velocity = Vector2.zero;          // 清速度
    rb.isKinematic = false;              // 恢复物理
    spriteRenderer.sprite = originalSprite;  // 恢复精灵
}

private IEnumerator ReturnAfterDelay(float delay)
{
    yield return new WaitForSeconds(delay);
    PoolManager.Instance.Return(gameObject);  // ⭐ 归还池中，不再 Destroy
}
```

#### 为什么这样改？

| 原来的 Start()  | 现在的 OnGetFromPool() |
| ------------ | ------------------- |
| 只在首次创建时调用一次  | 每次从池取出都调用           |
| Destroy 销毁对象 | Return 归还对象         |
| 无法重置状态       | 可以重置精灵、速度等          |

> **关键**：Start() 只执行一次，但池化对象会被反复使用。所以必须把初始化逻辑移到 OnGetFromPool()，每次取出都重新初始化。

### 3.4 PlayerBow\.cs 修改了什么

```csharp
// 原来
Arrow arrow = Instantiate(arrowPrefab, ...).GetComponent<Arrow>();

// 现在
GameObject arrowObj = PoolManager.Instance.Get(arrowPrefab, launchPoint.position, Quaternion.identity);
Arrow arrow = arrowObj.GetComponent<Arrow>();
arrow.Launch(shootDirection);
```

就改了一行：`Instantiate` → `PoolManager.Instance.Get`。

## 四、对象池的完整生命周期

```
第一次射箭（池为空）：
    PoolManager.Get()
        → 队列空 → Instantiate 创建箭矢A
        → Awake() 记录原始精灵
        → SetActive(true)
        → OnGetFromPool() 设伤害、启动1秒计时器
        → 返回箭矢A
    → arrow.Launch() 设置方向和速度
    → 箭矢飞行...

1秒后（计时器到期）：
    → ReturnAfterDelay 协程触发
    → PoolManager.Return(箭矢A)
        → OnReturnToPool() 清速度、恢复精灵
        → SetActive(false) 隐藏
        → 放入队列

第二次射箭（池中有箭矢A）：
    PoolManager.Get()
        → 队列有箭矢A → 取出
        → SetActive(true) 显示
        → OnGetFromPool() 设伤害、启动新计时器
        → 返回箭矢A（复用！）
    → arrow.Launch() 设置方向和速度

循环往复，不再 Instantiate。
```

## 五、在 Unity 中怎么使用

### 步骤1：添加 PoolManager 到场景

1. 打开 `PersistentScene`
2. 在 `GlobalManagers` 下新建空物体 `PoolManager`
3. 添加 `PoolManager` 脚本组件
4. PoolManager 不需要任何 Inspector 配置，自动运行

### 步骤2：验证

| 步骤 | 操作            | 预期结果                     |
| -- | ------------- | ------------------------ |
| 1  | 运行游戏          | 无报错                      |
| 2  | 切弓射击          | 箭矢正常飞行                   |
| 3  | 射第二箭          | 箭矢正常飞行（复用第一个箭矢）          |
| 4  | 连续射10箭        | Hierarchy 里箭矢数量不增长（池中复用） |
| 5  | 暂停看 Hierarchy | 有非激活的箭矢对象在池中等待           |

### 步骤3（可选）：预热池

在游戏开始时提前创建几个箭矢，避免首次射箭的卡顿：

```csharp
// 在任意脚本的 Start() 中调用
[SerializeField] private GameObject arrowPrefab;

void Start()
{
    PoolManager.Instance.Prewarm(arrowPrefab, 5);  // 提前创建5个箭矢
}
```

## 六、边界情况处理

### 情况1：箭矢插在敌人身上，敌人死亡被销毁

箭矢是敌人的子物体，敌人 Destroy → 箭矢也被 Destroy → 不会归还池中。

**处理**：池中少了一个箭矢，下次 Get() 发现队列为空 → 自动 Instantiate 新的。不会崩溃，只是多一次实例化。

### 情况2：PoolManager 不在场景中

PoolManager.Instance 为 null。

**处理**：Arrow 的 ReturnAfterDelay 有兜底逻辑：

```csharp
if (PoolManager.Instance != null)
    PoolManager.Instance.Return(gameObject);
else
    Destroy(gameObject); // 兜底：直接销毁
```

### 情况3：箭矢归还时仍附着在敌人身上

OnReturnToPool 重置了精灵和物理，PoolManager.Return 调用了 `transform.SetParent(null)` 脱离父级。

**处理**：箭矢干净地脱离敌人，放回池中。

## 七、性能对比

| 指标    | 优化前                           | 优化后               |
| ----- | ----------------------------- | ----------------- |
| 每次射箭  | 1 次 Instantiate + 1 次 Destroy | 0 次（池中有空闲时）       |
| GC 压力 | 每箭都产生垃圾回收                     | 几乎为零              |
| 内存    | 随箭矢数量波动                       | 稳定（池大小固定后）        |
| 首次射箭  | 正常速度                          | 正常速度（Instantiate） |
| 后续射箭  | 正常速度                          | 更快（直接 SetActive）  |

## 八、面试考点

**Q：为什么要用对象池？不用行不行？**
A：频繁创建销毁 GameObject 会导致 GC 卡顿和内存碎片。对象池通过"复用"避免反复实例化，是 Unity 游戏开发的标准实践。

**Q：对象池的池大小应该设多大？**
A：根据同时存在的最大对象数量。箭矢的 lifeSpan 是 1 秒，冷却时间约 0.3 秒，所以同时最多约 3-4 个箭矢在飞行。池大小设为 5 就够了。

**Q：如果池中对象被意外销毁怎么办？**
A：Get 方法在 Dequeue 时会跳过 null 引用，队列为空时自动 Instantiate 新对象，保证不会返回已销毁的实例。

**Q：为什么用接口 IPoolable 而不是直接在基类里写？**
A：解耦。PoolManager 只认接口不认具体类，任何对象只要实现 IPoolable 就能用池，不强制继承某个基类。
