# ⭐ Lv1：认识项目

## 第1章 项目总览

### 1.1 这是什么游戏？

这是一个 **2D 俯视角 ARPG**（动作角色扮演游戏），类似简化版《塞尔达》/《元气骑士》。

| 特性 | 说明 |
|------|------|
| 🗡️ 战斗 | 近战剑斩 + 远程弓箭，可切换 |
| 👾 敌人 | 有 AI 寻路追踪、攻击、击退 |
| 🗺️ 场景 | 多场景切换，带淡入淡出过渡 |
| 🎒 背包 | 拾取、堆叠、使用、丢弃物品 |
| 💬 对话 | 多分支对话树，有条件触发 |
| 📜 任务 | 接取、追踪、完成、奖励 |
| 🏪 商店 | 买卖物品、武器、防具 |
| 🌳 技能 | 技能树，前置解锁，属性加成 |
| 💾 存档 | 自动存档 + 手动存档，JSON 序列化 |
| 📱 平台 | 支持 PC + 安卓（虚拟摇杆） |

### 1.2 怎么运行？

**在 Unity 中打开项目的步骤：**

1. 打开 Unity Hub → `Add` → 选择 `d:\my_arpg-master` 文件夹
2. 等待 Unity 导入资源（首次较慢）
3. 打开场景：`Assets/Scenes/InitialScene.unity`
4. 点击 ▶️ Play

> ⚠️ **必须从 InitialScene 启动！** 不要直接打开 Scene1 或 PersistentScene，否则场景加载链会断裂。

**验证项目正常的标志：**
- 进入游戏后看到主菜单
- 点击"开始游戏"进入 Scene1
- 能用 WASD/虚拟摇杆移动角色
- 按攻击键能挥剑

# ⭐⭐ Lv2：架构基石

## 第3章 场景架构（最核心！）

### 3.1 一句话理解

> 这个游戏**不是**传统的"一个场景一个关卡"。它用 **1个启动场景 + 1个常驻场景 + N个内容场景** 的三层架构。

### 3.2 三层场景模型

```
┌─────────────────────────────────────────────────┐
│  InitialScene（启动场景）                         │
│  唯一在 Build Settings 中的场景                   │
│  只做一件事：加载 PersistentScene                  │
│  脚本：InitialLoad.cs（仅12行）                   │
└──────────────────────┬──────────────────────────┘
                       │ Addressables.LoadSceneAsync
                       ▼
┌─────────────────────────────────────────────────┐
│  PersistentScene（常驻场景）⭐ 最重要              │
│  一旦加载就永远不卸载                              │
│  包含：玩家、所有UI、所有管理器、相机              │
│  这是游戏的"骨架"                                 │
└──────────────────────┬──────────────────────────┘
                       │ 按需加载/卸载
              ┌────────┼────────┐
              ▼        ▼        ▼
        ┌─────────┐┌─────────┐┌──────────────┐
        │ Scene1  ││ Scene2  ││ StartingMenu │
        │ 关卡1   ││ 关卡2   ││ 主菜单       │
        │(地形+怪)││(地形+怪)││(按钮+背景)   │
        └─────────┘└─────────┘└──────────────┘
        这些是"内容场景"，用 Additive 模式叠加
```

### 3.3 为什么这样设计？

| 传统做法 | 本项目做法 | 好处 |
|----------|-----------|------|
| 每个关卡一个完整场景 | 玩家和UI放常驻场景 | 切场景时玩家不销毁 |
| 切场景=加载整个新场景 | 只卸载旧内容+加载新内容 | 加载快，无闪烁 |
| 管理器用 DontDestroyOnLoad | 管理器在常驻场景里 | 更可控，不污染全局 |

### 3.4 启动流程（逐行跟踪）

**第1步：InitialScene 加载**
- 文件：`Assets/Scripts/InitialLoad.cs`
- 只有 12 行代码，做一件事：

```csharp
// InitialLoad.cs 核心逻辑
private void Awake() {
    Addressables.LoadSceneAsync(persistentScene); // 异步加载常驻场景
}
```

**第2步：PersistentScene 加载完成**
- `SceneChanger`（常驻场景中的单例）在 `Awake` 时初始化
- 调用 `OnSingletonInitialized()` → 加载第一个内容场景（主菜单或 Scene1）

**第3步：内容场景叠加**
- `SceneChanger.LoadScene()` 用 `LoadSceneMode.Additive` 叠加内容场景
- 玩家、UI 都在常驻场景里，不受内容场景切换影响

### 3.5 🔍 在 Unity 中查看

| 步骤 | 操作 | 看什么 |
|------|------|--------|
| 1️⃣ | `File > Build Settings` | 确认只有 InitialScene 在列表中 |
| 2️⃣ | 双击打开 `InitialScene` | Hierarchy 里只有一个对象+InitialLoad 脚本 |
| 3️⃣ | 选中该对象看 Inspector | `persistentScene` 字段引用了 Addressable 资源 |
| 4️⃣ | 双击打开 `PersistentScene` | 看到 Player、UICanvas、各种 Manager |
| 5️⃣ | 双击打开 `Scene1` | 只有地形、敌人、NPC、传送点 |
| 6️⃣ | 运行游戏，看 `Hierarchy` | 切场景时 PersistentScene 的对象不变 |

> 💡 **关键观察**：运行时在 Hierarchy 窗口，你会看到多个场景同时存在。`PersistentScene` 始终在，`Scene1`/`Scene2` 会被替换。

### 3.6 场景类型枚举


## 第4章 三大设计模式基石

### 4.1 单例模式（YSingleton）

**是什么：** 保证一个类只有一个实例，全局可访问。

**文件：** `Assets/Scripts/Contracts/YSingleton.cs`

```csharp
public abstract class YSingleton<T> : MonoBehaviour where T : MonoBehaviour
{
    protected static T _instance;
    public static T Instance => _instance;  // 全局访问入口

    protected virtual void Awake()
    {
        if (_instance != null && _instance != this)
        {
            Destroy(gameObject);  // 重复实例→销毁
            return;
        }
        _instance = this as T;
        OnSingletonInitialized();  // 子类初始化钩子
    }
}
```

**怎么用：** `class StatsManager : YSingleton<StatsManager> { }`
然后任何地方：`StatsManager.Instance.GetDamage()`

**项目中的单例清单：**

| 单例 | 职责 |
|------|------|
| `PlayerController` | 玩家位置访问 |
| `PlayerHealth` | 玩家血量 |
| `StatsManager` | 玩家所有数值 |
| `ExpManager` | 经验与升级 |
| `SceneChanger` | 场景切换 |
| `DataManager` | 存档数据中心 |
| `SaveSystem` | 存档读写 |
| `UIManager` | UI 调度 |
| `QuestManager` | 任务管理 |
| `ShopManager` | 商店管理 |
| `DialogManager` | 对话管理 |
| `InventoryManager` | 背包管理 |
| `AStarPathFinder` | A*寻路 |
| `AStarNodeManager` | 寻路网格 |
| `TimeManager` | 时间暂停 |
| `RetryManager` | 重试 |
| `ConversationHistoryManager` | 对话历史 |

### 4.2 ScriptableObject 事件系统（最精妙的设计！）

**是什么：** 用 ScriptableObject 资产作为"事件通道"，实现跨场景、跨对象的解耦通信。

**为什么不用普通 C# 事件？**

| 普通 C# 事件 | SO 事件 |
|-------------|---------|
| 订阅者和发布者必须在同一场景 | 跨场景工作（SO 是资产，不随场景销毁） |
| 需要找到对方引用 | 只需引用同一个 SO 资产 |
| 场景切换后订阅丢失 | SO 资产持久存在 |

**工作原理图：**

```
  发布者（场景A的脚本）          SO事件资产           订阅者（常驻场景的脚本）
  ┌──────────────┐        ┌──────────────┐        ┌──────────────┐
  │ Teleport     │──引用──▶│SceneLoadEvent│◀──引用──│ SceneChanger │
  │ (触发传送)    │        │    SO        │        │ (执行切换)    │
  └──────────────┘        └──────────────┘        └──────────────┘
       调用 Raise              事件通道              订阅并响应
```

**项目中的 SO 事件清单：**

| SO 事件 | 参数 | 用途 |
|---------|------|------|
| `VoidEventSO` | 无 | 通用空事件 |
| `SceneLoadEventSO` | 场景+位置+是否淡入 | 请求切场景 |
| `ToggleCanvasEventSO` | bool开关 | 开关UI画布 |
| `DataSaveEventSO` | 存档类型 | 触发写存档 |
| `LootEventSO` | 物品+数量+Loot对象 | 拾取物品 |
| `InventorySlotsStatsSO` | 物品+价格+数量 | 商店买卖 |
| `LoadQuestEventSO` | 任务列表 | 加载任务板 |
| `QuestOptionsEventSO` | 任务状态 | 任务选项 |

**🔍 在 Unity 中查看 SO 事件：**

| 步骤 | 操作 |
|------|------|
| 1️⃣ | `Project` 窗口 → `Assets > GameSO` |
| 2️⃣ | 找到 Events 子文件夹 |
| 3️⃣ | 点击任意事件资产（如 `SceneLoadEventSO`） |
| 4️⃣ | Inspector 显示 `canvasToToggle` 等字段 |
| 5️⃣ | 在 Hierarchy 选中 `SceneChanger` 对象 |
| 6️⃣ | Inspector 中 `loadEventSO` 字段拖的就是同一个资产 |

> 💡 **验证技巧**：把同一个 SO 事件资产拖给两个不同脚本的对应字段，它们就"连线"了。这就是 SO 事件的本质——**共享资产引用**。

### 4.3 接口（契约层）

**文件：** `Assets/Scripts/Contracts/`

| 接口 | 方法 | 谁实现 | 作用 |
|------|------|--------|------|
| `IDamageable` | `TakeDamage(damage, attacker)` | `EnemyHealth` | 统一受伤入口 |
| `ISaveable` | `SaveData/LoadData/Register` | 敌人/物品/背包等 | 统一存档入口 |
| `ICanvasManager` | `ToggleCanvas/SetCanvaState` | 各UI管理器 | 统一画布开关 |

**IDamageable 的妙处：**
```csharp
// 玩家攻击时不需要知道打的是谁
var damageable = enemy.GetComponent<IDamageable>();
if (damageable != null)
    damageable.TakeDamage(damage, transform);
// 只要实现了 IDamageable，就能被打——敌人、木箱、未来的Boss都行
```

**🔍 在 Unity 中理解接口：**
- 接口本身不挂在对象上，它是"约定"
- 看 `EnemyHealth.cs` 的类声明：`public class EnemyHealth : MonoBehaviour, IDamageable, ISaveable`
- 这表示 EnemyHealth 承诺实现这两个接口的所有方法

### 5.2 状态机（PlayerMovement）

**文件：** `Assets/Scripts/Gameplay/Player/PlayerMovement.cs`

玩家有 5 个状态：

```
         ┌──────────────────────────────────┐
         │                                  │
         ▼                                  │
  ┌──────────┐  有输入   ┌──────────┐      │
  │   Idle   │─────────▶│ Running  │      │
  │  待机    │◀─────────│  奔跑    │      │
  └──────────┘  无输入   └──────────┘      │
       │                                   │
       │ 按攻击键                           │
       ▼                                   │
  ┌──────────┐  动画结束事件               │
  │Attacking │────────────────────────────▶│
  │  攻击    │  (VoidEventSO)              │
  └──────────┘                             │
       │                                   │
       │ 按射击键                           │
       ▼                                   │
  ┌──────────┐  动画结束事件               │
  │ Shooting │────────────────────────────▶│
  │  射击    │  (VoidEventSO)              │
  └──────────┘                             │
                                           │
  ┌──────────┐  被敌人打                   │
  │KnockBack │◀────────────────────────────┘
  │  击退    │──计时器结束──▶ Idle
  └──────────┘
```

**核心机制：`canBeInterrupted` 锁**

```csharp
private bool canBeInterrupted = true; // 是否可被打断

// Update 中：
if (!canBeInterrupted) return;  // 攻击/射击中→不处理新输入
else MovementSM();              // 正常→执行状态机

// 进入攻击状态时：
canBeInterrupted = false;  // 锁定，防止攻击动画被打断

// 动画播放完毕，通过 SO 事件解锁：
private void OnActionFinished() {
    canBeInterrupted = true;  // 解锁
    AnimatorSM(PlayerState.Idle);
}
```

> 💡 **通俗理解**：`canBeInterrupted` 就像"技能读条"。攻击动画播放时锁住输入，动画播完通过**动画事件**触发 SO 事件，解锁输入。

### 5.3 动画事件链（重要！）

**问题：** 动画播放到某一帧时，怎么通知代码"现在该造成伤害了"？

**答案：** Unity 动画事件 → `PlayerAnimationEventRelay` → 实际逻辑

```
动画片段(.anim)中设置 Animation Event
        │
        ▼ 调用 PlayerAnimationEventRelay 的方法
┌─────────────────────────────────┐
│ PlayerAnimationEventRelay       │  ← 挂在 Player 根对象
│ （动画事件中继器）               │
│                                 │
│ DealDamage() → 检查剑是否激活    │
│ Shoot()      → 检查弓是否激活    │
│ FinishCombat() → 通知攻击结束    │
└─────────────────────────────────┘
```

## 第8章 A* 寻路算法（面试重点！）

### 8.1 什么是 A*？

> A* 是一种**最短路径搜索算法**。想象你在迷宫里，A* 就是那个"聪明地"找到最短路径的方法——它不会盲目地走，而是"预估"哪个方向更可能到达终点。

### 8.2 核心公式

```
F = G + H

G = 从起点到当前节点的实际代价（已走的路）
H = 从当前节点到终点的预估代价（还要走的路，用曼哈顿距离估算）
F = 总代价（越小越优先）
```

**本项目的 H 计算（曼哈顿距离）：**
```csharp
// PathFinderDetails.cs
private float CalDistance(int ax, int ay, int bx, int by) {
    int distance = |bx-ax| + |by-ay|;  // 曼哈顿距离
    return distance >= 2 ? 1.414f : 1; // 对角≈1.414，直线=1
}
```

### 8.3 算法流程（通俗版）

```
1. 把起点放入"待检查列表"（Open List）
2. 循环：
   a. 从 Open List 中取 F 值最小的节点 → 当前节点
   b. 如果当前节点是终点 → 找到路径！回溯父节点得到完整路径
   c. 把当前节点移到"已检查列表"（Close List）
   d. 检查当前节点的 8 个邻居：
      - 是障碍物？跳过
      - 在 Close List 中？跳过
      - 不能对角穿过墙角？跳过
      - 不在 Open List？加入，设当前节点为父节点
      - 已在 Open List？如果新路径 G 值更小，更新父节点
3. Open List 空了还没找到 → 没有路径
```

### 8.4 项目中的实现

**三个核心类：**

| 类 | 职责 | 通俗理解 |
|----|------|---------|
| `AStarNode` | 网格中的一个格子 | 地图上的一个小方格 |
| `AStarNodeManager` | 构建整个网格 | 把地图变成棋盘 |
| `AStarPathFinder` | 执行 A* 算法 | 在棋盘上找路 |
| `PathFinderDetails` | 寻路过程中的节点信息 | 记录"我从哪来，代价多少" |
| `MovementController` | 沿路径移动 | 按照找到的路走 |

**是什么：** 一个链表，记录画布打开的顺序。最后打开的在最上面。

```csharp
public interface ICanvasManager {
```

```csharp
// 用 CanvasGroup.alpha 控制整体透明度
private IEnumerator FadeCanvasGroup(float from, float to, float duration) {
    fadeCanva.alpha = from;
    float elapsed = 0f;
    while (elapsed < duration) {
        elapsed += Time.unscaledDeltaTime;  // 不受时间缩放影响
        float t = Mathf.Clamp01(elapsed / duration);
        fadeCanva.alpha = Mathf.Lerp(from, to, t);
        yield return null;
    }
    fadeCanva.alpha = to;
}
```

> 💡 **面试考点**：为什么用 `Time.unscaledDeltaTime`？
> 答：场景切换时 `TimeManager.PauseGame()` 把 `timeScale` 设为 0，`Time.deltaTime` 会变成 0，协程会卡住。`unscaledDeltaTime` 不受 `timeScale` 影响，保证淡入淡出正常播放。

# 🏆 Lv6：面试拷打题库

## 第18章 面试高频问题

### 18.1 架构类

**Q1：你的项目场景是怎么组织的？为什么不用传统的单场景？**

> 答：项目用三层场景架构。`InitialScene` 是启动场景，只负责加载 `PersistentScene`。`PersistentScene` 是常驻场景，包含玩家、UI、所有管理器，永不卸载。`Scene1`/`Scene2` 等内容场景用 Addressables 的 Additive 模式按需加载/卸载。
>
> 好处：切场景时玩家和 UI 不销毁，无需 DontDestroyOnLoad；加载快，只换内容部分；管理器集中在常驻场景，生命周期可控。

**Q2：为什么用 ScriptableObject 做事件系统？**

> 答：SO 事件解决了跨场景通信问题。普通 C# 事件的订阅者和发布者必须在同一场景，场景切换后订阅丢失。SO 是资产文件，不随场景销毁，发布者和订阅者只需引用同一个 SO 资产即可通信。而且 SO 事件在 Inspector 中可视化连线，便于调试。

**Q3：项目中用了哪些设计模式？**

> 答：
> - **单例模式**：`YSingleton<T>` 泛型基类，所有管理器都是单例
> - **观察者模式**：SO 事件系统、`EnemyHealth.OnDefeated` 静态事件
> - **状态机模式**：玩家 `PlayerMovement`、敌人 `EnemyMovement`、NPC `NPCStateController`
> - **策略模式**：`ISaveable` 接口，不同对象实现不同的存档策略
> - **命令模式**（变体）：动画事件通过 `PlayerAnimationEventRelay` 路由

### 18.2 战斗类

**Q4：攻击判定怎么实现的？**

> 答：用 `Physics2D.OverlapCircleAll` 在攻击点画圆检测。攻击时机由动画事件控制——动画播放到特定帧触发 `DealDamage`。检测到敌人后通过 `IDamageable` 接口统一调用 `TakeDamage`，不关心具体是什么敌人。

**Q5：怎么防止攻击动画被打断？**

> 答：`canBeInterrupted` 标志。进入攻击状态时设为 false，Update 中检查此标志，为 false 则不处理新输入。动画播放完毕通过动画事件触发 SO 事件，`OnActionFinished` 中恢复为 true。

**Q6：近战和远程怎么切换的？**

> 答：`ShiftEquipment` 脚本监听切换键，翻转 `PlayerCombat.IsActive` 和 `PlayerBow.IsActive`。`PlayerAnimationEventRelay` 根据 IsActive 把动画事件路由到对应武器。弓还通过 `Animator.SetLayerWeight` 切换动画层。

### 18.3 AI 类

**Q7：敌人 AI 怎么工作的？**

> 答：状态机驱动。每 0.2 秒用 `OverlapCircle` 检测玩家。玩家在攻击范围内且冷却完毕→攻击；在追踪范围内→A*寻路追踪；超出范围→待机。被攻击时进入击退状态，协程计时后恢复。

**Q8：A* 算法的核心是什么？你的实现有什么优化？**

> 答：核心是 `F = G + H`，每次取 F 最小的节点扩展。G 是起点到当前的实际代价，H 是当前到终点的预估代价（曼哈顿距离）。
>
> 优化：
> 1. 安全边距：路径点远离障碍物，防卡脚
> 2. 对角线限制：不能穿墙角
> 3. 优化起点：追踪时从靠近玩家的点开始寻路，避免绕远
> 4. 重寻路冷却：目标移动时不每帧重算，有冷却时间
> 5. 检测频率：敌人每 0.2 秒检测一次，不是每帧

**Q9：A* 的 Open List 你用什么数据结构？有什么改进空间？**

> 答：当前用 `Dictionary` 存 Open List，每次取最小 F 值需要遍历，是 O(n)。改进方案是用**最小堆（优先队列）**，取最小值 O(1)，插入 O(log n)。代码注释中也提到了这个 TODO。

### 18.4 存档类

**Q10：存档系统怎么设计的？**

> 答：三层架构。`ISaveable` 接口定义存档契约，所有需要存档的对象实现它并在 Awake 时注册到 `DataManager`。`DataManager` 是数据中心，持有 `Data` 对象，场景切换时遍历所有注册对象收集数据。`SaveSystem` 负责 JSON 序列化和文件读写。

**Q11：怎么保证每个对象都能被正确识别？**

> 答：`DataDefinition` 组件，每个可存档对象挂一个，有唯一 GUID。存档时用 GUID 作为字典键，读档时通过 GUID 找到对应数据。`OnValidate` 中自动生成 GUID，保证编辑器中不会重复。

**Q12：自动存档和手动存档有什么区别？**

> 答：自动存档（SystemSave）在场景切换时触发，保存的是目标场景和入口位置。手动存档（PlayerSave）由玩家主动触发，保存的是玩家当前位置。读档时"继续游戏"加载最新的系统存档，"加载存档"加载玩家选择的手动存档。

**Q13：为什么读档时要防止自动存档？**

> 答：读档也会触发场景加载事件，如果不加判断，`OnAutoSave` 会采集当前（即将卸载）场景的数据，污染刚读出的存档快照。所以用 `IsLoadingSaveRequest` 标志，读档时跳过自动存档。

### 18.5 UI 类

**Q14：多个 UI 面板怎么管理层级？**

> 答：`CanvasFocusStack` 用链表记录打开顺序。最后打开的在链表末尾，`sortingOrder` 最高（90）。每往下一层减 10。ESC 键关闭链表末尾的面板。拖拽面板时调用 `HandleFocus` 移到末尾置顶。

**Q15：画布开关为什么用 CanvasGroup 而不是 SetActive？**

> 答：`CanvasGroup` 可以控制 alpha（透明度）、blocksRaycasts（射线）、interactable（交互），实现"隐藏但保留状态"。`SetActive(false)` 会触发 `OnDisable`，可能丢失状态或触发不需要的逻辑。而且 CanvasGroup 支持渐变动画。

### 18.6 性能类

**Q16：项目中有哪些性能优化？**

> 答：
> 1. 敌人检测每 0.2 秒一次，不是每帧
> 2. A* 重寻路有冷却时间
> 3. 场景用 Addressables 异步加载，不卡主线程
> 4. 淡入淡出用 `unscaledDeltaTime`，不受暂停影响
> 5. `AdaptiveOrthoSize` 只在分辨率变化时重算
> 6. 背包槽位用对象池思想，空槽 inactive 而非销毁

**Q17：如果敌人数量很多，A* 寻路怎么优化？**

> 答：
> 1. 分帧寻路：不是所有敌人同帧寻路，错开计算
> 2. 路径缓存：相同起终点的路径缓存复用
> 3. 分层寻路：远处敌人用粗粒度网格，近处用细粒度
> 4. 动态障碍：用局部避障代替全局重寻路
> 5. 最小堆优化 Open List

### 18.7 踩坑类

**Q18：项目中遇到过什么坑？怎么解决的？**

> 答：（根据项目记忆）
> 1. **中文字体问题**：TextMeshPro 默认不含中文字形，需要 `ChineseSDF.asset` 作为 fallback，且用动态图集模式运行时生成字形
> 2. **场景切换白屏**：`SceneChanger` 变量名冲突导致编译错误，修改时需注意不破坏现有逻辑
> 3. **圆形遮罩模糊**：运行时生成纹理会模糊，改用 Unity 内置 Filled Radial UI Image
> 4. **List 用 .Count 不是 .Length**：C# 的 `List<T>` 用 `.Count`，数组才用 `.Length`
> 5. **Confiner 警告**：场景加载时序问题，等一帧再查找 Confiner 对象
